KEY REQUIREMENTS EXTRACTED
================================================================================

Authentication & Authorization:
✅ BCrypt ≥12 or Argon2id password hashing
✅ JWT access token (15min) + rotating refresh tokens
✅ OTP with E.164 normalization, hashing, 5min expiry, 5 attempts, rate-limiting
✅ RBAC with ROLE_ADMIN for sensitive operations
✅ Server-side ownership checks on all customer resources
✅ Session revocation and device binding support

Data & Money:
✅ PostgreSQL DECIMAL(10,2) for all money fields
✅ Java BigDecimal for calculations (never float/double)
✅ Explicit rounding (HALF_UP mode)
✅ Server-side price, discount, tax, shipping, total calculation

Orders & Inventory:
✅ Idempotent order creation (via idempotency key)
✅ Transactional stock decrement with optimistic locking
✅ Order status only via backend/admin (never client)
✅ Cancellation eligibility from server Order.created_at
✅ OrderStatusHistory logging on every transition

API:
✅ Version /api/v1
✅ Validate all DTOs, reject unknown fields
✅ Pagination limits enforced (max 100 items)
✅ Correlation ID on all responses
✅ Consistent error envelope, no production stack traces

Observability:
✅ Structured JSON logging with correlation IDs
✅ Audit logging for sensitive actions (never log secrets/PII)
✅ /actuator/health endpoint
✅ Micrometer metrics (latency, errors, cache, search)

Security:
✅ Never commit secrets to repo
✅ HTTPS enforced in production
✅ Security headers (X-Frame-Options, X-Content-Type-Options)
✅ CORS properly configured
✅ SQL injection prevention (parameterized queries)
✅ Input validation and sanitization
✅ Redis-backed rate limiting

Testing:
✅ Unit test coverage ≥80%
✅ Integration tests (database, transactions)
✅ Endpoint tests (REST layer)
✅ Concurrency tests (stock decrement, order creation)
✅ Security tests (ownership, RBAC, authorization)

GOLDEN RULE (Remember Always)
================================================================================

All authoritative business, security, pricing, stock, and authorization rules
belong on the SERVER.

Never trust client:
  ❌ price, discount, totals, effective price
  ❌ stock levels
  ❌ ownership claims
  ❌ payment success confirmation
  ❌ cancellation eligibility
  ❌ security timestamps

Always:
  ✅ Validate and recalculate server-side
  ✅ Check ownership and authorization
  ✅ Use transactions for multi-step operations
  ✅ Audit sensitive actions
  ✅ Log structured JSON with correlation IDs
